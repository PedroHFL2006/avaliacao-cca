================================================================================
1. CRITÉRIOS DA ANÁLISE
================================================================================
- Linguagem: C99, com VLA nos parâmetros das funções. Todo o código está
  no arquivo main.c.
- Cada linha do pseudocódigo executada custa 1 instrução.
- Um laço "para" que repete x vezes tem a linha do cabeçalho executada
  x + 1 vezes (a última é o teste que encerra o laço). O mesmo vale para o
  "enquanto".
- A análise é sempre do PIOR CASO, e todas as 5 funções usam o mesmo método:
  T(n) é a soma dos custos de todas as linhas.
- Computador de 10^8 instruções por segundo:
      Tempo (s) = T(n) / 10^8

================================================================================
FUNÇÃO 1: Contagem de ocorrências
================================================================================
Pior caso: todo V[j] é igual a K_vec[i], então o "se" é sempre verdadeiro.

Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função contagem_ocorrencias(V, n, K_vec, k):
 1  soma_total <- 0                                 1
 2  para i <- 0 até k-1 faça                        k + 1
 3      contador <- 0                               k
 4      para j <- 0 até n-1 faça                    k(n + 1) = kn + k
 5          se V[j] = K_vec[i] então                kn
 6              contador <- contador + 1            kn
        fim_se
    fim_para
 7      soma_total <- soma_total + contador         k
    fim_para
 8  retorne soma_total                              1
fim_função

T(n, k) = 1 + (k + 1) + k + (kn + k) + kn + kn + k + 1
T(n, k) = 3kn + 4k + 3

Big-O: O(k·n)

Tempo para n = 50.000 e k = 4.000:
  T = 3·(4.000·50.000) + 4·4.000 + 3
    = 600.000.000 + 16.000 + 3
    = 600.016.003 instruções
  Tempo = 600.016.003 / 10^8 ≈ 6,00 segundos

================================================================================
FUNÇÃO 2: Pares em matriz triangular
================================================================================
Pior caso: toda soma A[i][j] + A[j][i] é múltipla de 5.

O laço interno começa em j = i, então para cada i ele repete (n - i) vezes:
  soma das repetições = n + (n-1) + ... + 1 = n(n+1)/2
  cabeçalho do laço interno = soma de (n - i + 1) = n(n+1)/2 + n = n(n+3)/2

Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função analise_triangular(A, n):
 1  contador <- 0                                   1
 2  para i <- 0 até n-1 faça                        n + 1
 3      para j <- i até n-1 faça                    n(n+3)/2
 4          soma <- A[i][j] + A[j][i]               n(n+1)/2
 5          se soma mod 5 = 0 então                 n(n+1)/2
 6              contador <- contador + 1            n(n+1)/2
            fim_se
        fim_para
    fim_para
 7  retorne contador                                1
fim_função

T(n) = 1 + (n + 1) + n(n+3)/2 + 3·n(n+1)/2 + 1
     = n + 3 + (n² + 3n + 3n² + 3n)/2
     = n + 3 + 2n² + 3n
T(n) = 2n² + 4n + 3

Big-O: O(n²)

Tempo para n = 500:
  T = 2·250.000 + 4·500 + 3
    = 500.000 + 2.000 + 3
    = 502.003 instruções
  Tempo = 502.003 / 10^8 ≈ 0,00502 segundos (5,02 ms)

================================================================================
FUNÇÃO 3: Comparação de arranjos tridimensionais
================================================================================
Não há melhor nem pior caso: os dois arranjos são sempre percorridos inteiros.
Pior caso do final: somaA >= somaB é falso, então executa o "retorne 0"
(as duas saídas custam o mesmo).

Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função comparacao_3d(A, B, n):
 1  somaA <- 0                                      1
 2  para i <- 0 até n-1 faça                        n + 1
 3      para j <- 0 até n-1 faça                    n(n + 1) = n² + n
 4          para k <- 0 até n-1 faça                n²(n + 1) = n³ + n²
 5              somaA <- somaA + A[i][j][k]         n³
            fim_para
        fim_para
    fim_para
 6  somaB <- 0                                      1
 7  para i <- 0 até n-1 faça                        n + 1
 8      para j <- 0 até n-1 faça                    n² + n
 9          para k <- 0 até n-1 faça                n³ + n²
10              somaB <- somaB + B[i][j][k]         n³
            fim_para
        fim_para
    fim_para
11  se somaA >= somaB então                         1
12      retorne 1                                   0
    senão
13      retorne 0                                   1
    fim_se
fim_função

Custo de um bloco (linhas 1 a 5):
  1 + (n + 1) + (n² + n) + (n³ + n²) + n³ = 2n³ + 2n² + 2n + 2
O bloco de B (linhas 6 a 10) custa o mesmo.

T(n) = 2·(2n³ + 2n² + 2n + 2) + 2
T(n) = 4n³ + 4n² + 4n + 6

Big-O: O(n³)

Tempo para n = 300:
  T = 4·27.000.000 + 4·90.000 + 4·300 + 6
    = 108.000.000 + 360.000 + 1.200 + 6
    = 108.361.206 instruções
  Tempo = 108.361.206 / 10^8 ≈ 1,08 segundos

================================================================================
FUNÇÃO 4: Casos assimétricos no condicional
================================================================================
Os valores do vetor são limitados a 0..20 (20! é o maior fatorial que cabe em
um inteiro de 64 bits). O programa valida isso na leitura e recusa valores
fora da faixa.

Pior caso: todo V[i] é ímpar e igual a m = 19, o maior ímpar permitido
(número par não calcula fatorial, por isso 20 não é o pior caso).

Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função processar_vetor(V, n):
 1  somatorio <- 0                                  1
 2  para i <- 0 até n-1 faça                        n + 1
 3      se V[i] mod 2 = 0 então                     n
 4          somatorio <- somatorio + V[i]           0
        senão
 5          fat <- 1                                n
 6          para j <- 1 até V[i] faça               n(m + 1) = nm + n
 7              fat <- fat · j                      nm
            fim_para
 8          somatorio <- somatorio + fat            n
        fim_se
    fim_para
 9  retorne somatorio                               1
fim_função

T(n, m) = 1 + (n + 1) + n + 0 + n + (nm + n) + nm + n + 1
T(n, m) = 2nm + 5n + 3

Big-O: O(n·m). Como m é no máximo 19 (uma constante), fica O(n).

Tempo para n = 50.000 e m = 19:
  T = 2·50.000·19 + 5·50.000 + 3
    = 1.900.000 + 250.000 + 3
    = 2.150.003 instruções
  Tempo = 2.150.003 / 10^8 ≈ 0,0215 segundos (21,5 ms)

================================================================================
FUNÇÃO 5: Elementos de A presentes no vetor ordenado B
================================================================================
Pior caso: nenhum elemento de A existe em B. Assim cada busca binária faz o
número máximo de voltas e termina pelo "retorne 0".

Número de voltas da busca binária no pior caso:
  L = piso(log2 n) + 1

5.1 Busca binária
Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função busca_binaria(B, n, chave):
 1  inicio <- 0                                     1
 2  fim <- n - 1                                    1
 3  enquanto inicio <= fim faça                     L + 1
 4      meio <- inicio + (fim - inicio) div 2       L
 5      se B[meio] = chave então                    L
 6          retorne 1                               0
 7      senão se B[meio] < chave então              L
 8          inicio <- meio + 1                      L1
        senão
 9          fim <- meio - 1                         L2   (L1 + L2 = L)
        fim_se
    fim_enquanto
10  retorne 0                                       1
fim_função

Tb(n) = 1 + 1 + (L + 1) + L + L + 0 + L + L + 1
Tb(n) = 5L + 4

5.2 Função principal
Pseudocódigo                                        Custo (nº de execuções)
--------------------------------------------------------------------------------
função elementos_ordenados(A, B, n):
 1  total <- 0                                      1
 2  para i <- 0 até n-1 faça                        n + 1
 3      se busca_binaria(B, n, A[i]) = 1 então      n + n·Tb(n)
 4          total <- total + 1                      0
        fim_se
    fim_para
 5  retorne total                                   1
fim_função

(A linha 3 custa 1 pelo teste do "se", mais o custo da chamada da busca.)

T(n) = 1 + (n + 1) + n + n·(5L + 4) + 0 + 1
T(n) = 5nL + 6n + 3,   com L = piso(log2 n) + 1

Big-O: O(n log n)

Tempo para n = 10.000.000:
  log2(10.000.000) ≈ 23,25, então L = 23 + 1 = 24
  T = 5·10.000.000·24 + 6·10.000.000 + 3
    = 1.200.000.000 + 60.000.000 + 3
    = 1.260.000.003 instruções
  Tempo = 1.260.000.003 / 10^8 ≈ 12,6 segundos
